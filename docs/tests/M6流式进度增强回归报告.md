# M6+ 逐文件流式进度增强回归报告

- **日期**：2026-10-05
- **背景**：执行[项目进展记录](../../项目进展记录.md) §6 中 M6 增强候选（未排期）首项——**逐文件流式进度反馈**。原实现中批量结果整批一次性返回，转换过程中所有行统一显示"转换中…"，无法得知进展到第几个文件。
- **结论**：已实现并全量回归通过（**236 例：232 通过 / 4 既有 skip**）。

## 1. 行为变化

批量转换（多选/文件夹批量/重试，单文件同理）期间，**每个文件落定（成功/失败）即实时翻转对应结果行**：状态徽章、统计、警告、下载/打开按钮随单项结果就位，队列头部"成功 N"计数实时递增；不再需要等整批结束。最终整批结果的权威映射保持不变（流式事件只是提前渲染同一份数据）。

## 2. 实现口径

| 层 | 改动 |
|---|---|
| 渲染层 | `runConversion` 生成批次标记 `clientBatchId`（随 options 下发），订阅进度事件并按 `(batchId, index)` 把事件映射到本批次行（只更新仍为"转换中"的行）；批次结束清除关联。最终以返回值整批覆盖（幂等）。 |
| 桌面端 | `ConvertService.run` 增加可选 `onItem(index, item, jobId)` 回调——串行队列完成序 = 提交序，序号确定；**产物登记键（outputKey/downloadUrl）改为逐项分配**（随单项结果即时可用，打开/下载不等整批）；bridge 在渲染层传入 `clientBatchId` 时经 `convert:progress` IPC 事件推送（`webContents.send`，含销毁守卫；未传标记的旧调用路径零变化）。preload 暴露 `onConvertProgress(cb)` 订阅方法（返回退订函数）。 |
| 网页端 | `POST /api/convert` 增加 **Accept 协商**：请求头带 `application/x-ndjson` 时返回 NDJSON 流（每行一个 JSON 事件：`item` 逐文件推送 / 末行 `done` 携带完整 JobResult / 异常行 `error`），Fastify PassThrough 分块写出；**默认（无协商）仍返回完整 JSON**——既有客户端与 API 测试零破坏。`clientBatchId` 只在事件中回传，剥离后不进入 core 转换选项。 |
| 兼容 | 旧服务端 + 新渲染层：协商失败（响应非 NDJSON）自动回退整批 JSON 解析；新服务端 + 旧客户端：默认路径行为不变。 |

事件样例（NDJSON，桌面端 IPC 事件同构）：

```
{"type":"item","batchId":"b-…","jobId":"…","index":0,"item":{…单项结果…}}
{"type":"done","jobId":"…","items":[…完整结果数组…]}
```

## 4. E2E 备忘

- 流式断言的关键窗口：首个大文件完成（≈3s）到第二个完成（≈6s）之间，`.row.done`（首个）与 4 个 `.row.converting` 并存——这是"逐行翻转"的直接证据；
- 6MB 重复段落 ≈3s/文件（与集成回归同构造），保证取消/断言窗口充裕。
