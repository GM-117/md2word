# 图标更换报告（icon-v3 同步至网页 / 桌面应用 / 三平台安装包）

> 日期：2026-10-03 ｜ 触发：用户重新设计了品牌图标（icon-v3.svg，M→W 深色圆角底板），要求同步网页、app 与打包文件
> 图标源：`packages/renderer/src/assets/icon-v3.svg`（256 viewBox，深色圆角矩形 + 白色 M + 渐变转化箭头 + Word 蓝 W）

## 1. 变更内容

| 位置 | 旧状态 | 新状态 |
|---|---|---|
| 网页 favicon | 无（浏览器默认地球图标） | `public/icon.svg` + `index.html` `<link rel="icon" type="image/svg+xml">`（Vite 自动进 dist，web-host 与 app:// 均可服务） |
| 应用内顶栏 logo | 渐变紫底 + 内联文档箭头 SVG（IconBrand） | `<img src="/icon.svg">` 直用品牌图标（`.logo` 仅保留尺寸/投影；IconBrand 组件删除） |
| macOS 应用图标 | `build/icon.icns`（旧程序化绘制：蓝底文档+绿徽章） | 由 icon-v3.svg 重新生成（`iconutil` iconset 全尺寸 16–1024） |
| Windows 应用图标 | `build/icon.ico`，但 **exe 实际未嵌入**（`signAndEditExecutable: false` 跳过资源编辑，exe 保持 Electron 默认图标） | ico 由 icon-v3 重新生成（256px PNG-in-ICO）；**`signAndEditExecutable` 改为 true**——无证书时仅写图标/版本资源、自动跳过签名；NSIS 安装器图标同步生效 |
| 三平台安装包 | 旧图标 + 旧 renderer | 全部以新图标 + 新 renderer 重建（见 §2） |

**图标生成链路重写**（`packages/desktop/scripts/make-icon.mjs`）：旧脚本为纯 Node 程序化绘制（旧图案硬编码）；新脚本用 Playwright Chromium 将 SVG 按目标尺寸直接栅格化（内联 SVG 规避 about:blank 对 file:// 子资源的安全限制；`omitBackground` 保留圆角外透明），再经 `iconutil`（icns）与 PNG-in-ICO 打包（ico）。图标源单一化：网页 favicon、顶栏 logo、icns/ico 均出自 `renderer/src/assets/icon-v3.svg`。

## 3. 过程问题记录

1. **SVG 栅格化**：`page.setContent` 创建的 about:blank 页面无法加载 `file://` 图片（Chromium 安全策略），首版截图全黑——改为把 SVG 文本内联进页面并按尺寸改写根 `<svg>` 宽高（正则仅命中根标签属性，不影响 `stroke-width`）。
2. **yml 还原事故（同 D33 家族）**：批量构建间用脚本收窄/还原 `arch` 列表时，`str.replace` 全量替换误伤了 win nsis 的 `arch: [x64]`，一度产出 535MB 双架构 Setup（arm64 半边 sidecar 错配）。已修正 yml 并重建单架构 exe；verify-dist 架构断言可兜底拦截此类错配。

## 4. 遗留

- Windows 人工冒烟（W1–W7）时顺带确认：安装器与已安装 exe 的图标、任务栏/开始菜单图标均为新设计。
- `signAndEditExecutable: true` 后 electron-builder 不再跳过 exe 资源编辑；若未来接入签名证书无需再改配置。
- `build/` 在 gitignore 中（icns/ico 为本机构建资源，与旧图标时期一致）：**全新环境打包前需先运行 `node scripts/make-icon.mjs`**；M5 启用 release.yml 时建议把 make-icon 接入流水线。
