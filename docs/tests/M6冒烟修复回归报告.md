## 2. D35 —— 取消/失败后的重试计数不消解，可重复点击重复建任务

**现象**（用户冒烟实测）：14 个 md 批量转换中途取消，2 个文件提示"转换已被取消。"并出现「重试」；点击重试后该文件正常转换，但队列头部仍显示"重试失败项（2）"，可反复点击，反复创建转换任务并在 `.data/jobs` 生成新作业目录。

**根因**：重试的实现是"新起一行"（新结果插入列表首位），旧的失败行仍保持 `failed` 状态且携带重试数据源，而头部"重试失败项（N）"按全部失败行统计——旧行永远被计入，永不消解。

**修复**（renderer）：
- `RowState` 增加 `retried` 标记：点击重试（单行或一键全部）时，对应旧行立即标记"已重试"；
- "重试失败项（N）"只统计未重试过的失败行——重试后计数正确消解，重复点击入口随之消失；
- 已重试的旧行隐藏「重试」按钮，显示"已重新转换，结果见列表最新行。"提示；
- 若重试后再次失败（新行），新行照常计数与可重试（语义正确）。

## 3. 取消错误口径不统一（同属 D35 显示问题）

**现象**：批量取消后，在跑任务显示 `E_CANCELLED`"转换已被取消。"，而队列中未跑到的任务显示 `E_PANDOC_FAILED`"用户取消"（裸 rejection 文案），用户看到的失败信息不一致。

**修复**：core `queue.ts` 导出共享常量 `CANCEL_REASON = '用户取消'`，双端宿主（desktop ConvertService / web-host JobManager）把该 rejection 统一映射为 `E_CANCELLED`"转换已被取消。"。集成测试断言两台在跑/待执行任务均为统一口径。

## 4. D34 —— `.data/jobs` 作业目录无限累积

**现象**（用户观察）：每次转换在 `.data/jobs/<jobId>/`（含镜像的子目录，如 `tests/`）生成文件夹，只增不减。

**根因**：作业注册表是内存态，进程重启后历史作业目录全部不可达（下载/打开均被拒）但**从未被清理**——`cleanupJob` 有定义无调用；且桌面端纯 path 模式转换也会 `mkdirSync` 一个空 UUID 目录（桌面用户数据目录下同样累积）。

**修复**：
- **启动清扫**（web-host `JobManager` / desktop `createServices`）：启动时清空作业根目录下全部历史条目并记日志（`startup sweep: removed N stale job dir(s)`）。运行期间产生的作业目录保留（供下载/打开），到下次启动统一回收——对个人工具即"磁盘占用有上界（单次会话的量）"；
- **桌面端纯 path 模式不再创建作业目录**（产物本就落源文件目录，此前每次转换都留下一个空 UUID 目录）。

**用户既有数据**：仓库 `.data/jobs/` 下现存历史目录在本修复启动一次 web-host 后即被自动清空；该目录在 `.gitignore` 内，不影响版本库。

## 6. E2E 备忘（排障过程记录）

- 结果为整批一次性返回：行内无"转换中→完成"的中间态更新，取消窗口只能靠"取消按钮出现即点击"锁定（首个大文件 ≈2s 转换期）；
- 重复段落的超大文档 pandoc 处理极快（1MB 重复段落 < 200ms），构造慢转换需 4MB 级重复段落（与集成回归同一构造）；
- `setInputFiles` 注入的文件携带真实路径（path 模式），产物写源目录——E2E 输入一律用临时目录副本，避免污染仓库 `samples/`；
- 定位器 `.first()` 会随列表前置插入动态重解析：断言"旧行"须用 `nth(1)`。
