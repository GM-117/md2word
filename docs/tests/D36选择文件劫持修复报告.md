# D36 修复报告——「选择文件（可多选）」被劫持为文件夹对话框

- **日期**：2026-10-05
- **现象**（用户实测，桌面端打包应用）：点击拖放区「选择文件（可多选）」，弹出的却是文件夹类型对话框（与「选择文件夹（批量）」相同），无法多选 .md 文件。
- **结论**：已修复并回归（总账 **237 例：233 通过 / 4 既有 skip**），三平台安装包同步重建。

## 1. 根因（HTML label 隐式转发被劫持）

拖放区整体是 `<label class="dropzone">`，点击 label 内非交互元素（如「选择文件（可多选）」span、"把 .md 拖到这里"文案）时，浏览器把点击**隐式转发给 label 的第一个可标记（labelable）后代**。

- M6 之前：label 内唯一的 labelable 元素是隐藏的多选文件 input → 转发正确，弹出多选文件对话框；
- M6 之后：「选择文件夹（批量）」`<button>` 插入到 label 内、且**位于 file input 之前**——`<button>` 同样是 labelable 元素，于是成为 label 的转发目标。点击「选择文件」实际触发了文件夹按钮的 onClick → 打开文件夹对话框。

拖放区内其他非交互区域（图标/文案）同样被劫持，拖拽功能不受影响（drop 事件直连）。

## 2. 修复

`packages/renderer/src/App.tsx`：把隐藏的多选文件 input 移到 label 的**第一个子元素**位置（文件夹按钮之后于 DOM 无关紧要，关键是 input 成为第一个 labelable 后代），并在代码处留注释说明该约束。文件夹按钮自身是交互内容，label 不会向其转发点击，其行为不受影响；网页端结构同理核查（目录 input 本就在 label 外，无此问题）。
