## 4. 发现的问题及处理

### D25（真实缺陷 · 高优先级 · 已修复）

- **现象**（R3 首次运行暴露）：点击指向**未登记产物**的 `md2word://download/...` 链接（伪造链接、或应用重启后旧结果卡）时，协议处理器返回 404 裸响应，Chromium 将应用页面**导航**到 "not found" 错误文本页——界面丢失、无法返回，只能重启。
- **根因**：非 attachment 响应（错误状态）会被 Chromium 当作普通页面响应渲染；attachment 响应才进入下载管线。
- **修复**（`packages/desktop/src/main/index.ts`）：协议处理器对未登记/非法请求一律返回**空 attachment**（页面永不导航）；`will-download` 作为唯一安全闸门，对未登记产物 `event.preventDefault()` 取消下载——页面不动、不产生文件。修复后 R3 通过：无新文件、`location` 仍为 `app://bundle/index.html`。
- **回归**：修复后桌面 E2E 17/17 复跑通过；下载正常路径（T3/R1-R2 场景）不受影响。

### D26（测试脚本缺陷 · 3 处 · 已修正，非产品缺陷）

1. R6 体积换算误用字符数而非 UTF-8 字节数（18.7MB 未达 20MB 阈值，用例失效）→ 按 8 字节/单元重算 22.4MB。
2. I6 断言未考虑 XML 转义：pandoc 输出 `TOC \o &quot;1-2&quot;`（引号转义），正则修正。
3. I9 断言期望队列原因原文「用户取消」，而 core 对外暴露友好文案「转换已被取消。」→ 断言改为包含「取消」。
   > 三处均在新增用例**首次运行时**由回归本身捕获并修正——属测试代码质量问题，产品行为正确。
