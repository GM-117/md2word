# 图片资源与文件选择器优化回归报告（用户确认方案一）

- **日期**：2026-10-05
- **背景**：用户实测提出两点——①"选择文件（可多选）"对话框不筛选 md，出现"自定义文件"可选中 png/jpg；②只选图片后应用"无响应"（实际是反馈位置隐蔽），且不理解提示文案中"图片资源"的含义。经分析与方案沟通，**用户确认按方案一执行**（对话框 accept 收敛 + 反馈增强 + 分模式提示文案）。
- **结论**：已实现并全量回归通过（总账 **240 例：236 通过 / 4 既有 skip**）。

## 1. 问题定性（非崩溃，为体验缺陷）

- "无响应"根因：`convertFiles` 在所选内容不含任何 .md 时直接早退，仅在页面底部日志框写"未选择任何 .md 文件……"——日志框位于选项面板之下、视口外，用户体感即"没有任何反应"。转换队列保持为空属预期（无 md 可转）。
- 对话框不筛选 md：`accept=".md,.markdown,.mdown,.mkd,image/*"` 自 M2 起故意包含图片类型（为"md + 图片一次选齐"设计），代价是 Windows 文件类型下拉显示一长串"自定义文件"。
- "图片资源"概念未传达：拖放区提示文案未解释其用途与两种模式的差异。

## 2. 实现内容（方案一四项）

| # | 改动 | 说明 |
|---|---|---|
| 1 | `accept` 收敛为 `.md,.markdown,.mdown,.mkd` | 文件对话框只列 md 类型；图片资源带入途径不变——**拖拽本就不做类型过滤**（md+图片一起拖照常可用），网页端"选择文件夹（批量）"镜像上传覆盖子目录图片 |
| 2 | 仅选图片/非 md 文件时 **toast 明确反馈** | "未选择 .md 文件，已忽略 N 个文件；图片等资源需与 .md 一起拖入（用于内联文档引用）"，底部日志框保留（日志导出语境） |
| 3 | 提示文案**分模式显示**（经用户确认采用分模式而非统一文案） | 两种模式正确做法不同：桌面图片自动从原位置读取，网页需伴随上传。渲染层拖放区本就有 isDesktop 分支，成本一行条件 |
| 4 | 使用手册 §3.2 按模式拆分图片说明 | 同步"文件对话框只列 md"、"只选图片会弹提示"的行为 |

分模式文案（拖放区副标题）：

- **桌面模式**：`可多选 / 拖入 .md；文档引用的本地图片会自动从原位置读取，无需携带`
- **网页模式**：`可多选 / 拖入 .md；若引用了本地图片（相对路径），请连同图片一起拖入`

## 4. 使用指引（答复用户"该如何使用"）

- **桌面模式**：只管选/拖 md——文档里引用的本地图片会按相对/绝对路径自动从原位置读取并内联进 Word，不需要也不应该单独选图片。
- **网页模式**：文档引用了本地图片时，把 md 和图片**一起拖进**虚线框（可多文件拖拽）；或使用"选择文件夹（批量）"选择包含 md 与图片的文件夹（镜像上传保留相对路径）。
- 只选/只拖图片不会开始转换（无 md 可转），现在会得到明确的 toast 说明。
