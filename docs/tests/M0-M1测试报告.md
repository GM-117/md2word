### 性能基准（§5.1 四档；本机 macOS arm64）

| 档位 | 指标（§1.4） | 实测（端到端含管线） | 结论 |
|---|---|---|---|
| 1MB | < 2s | **1.25s**（pandoc 本体 1.16s） | ✅ |
| 10MB | < 15s | **11.5s**（pandoc 本体 10.8s） | ✅ 余量偏小，CI 机器需关注 |

**发现的重要边界（记录，不列为缺陷）**：pandoc 3.12 docx writer 对**列表极密集**文档存在性能上限——实测 10MB / 每节一个两项目列表（约 4 万列表）时 pandoc 本体耗时 ~110s（user 42s + system 15s）；同体量纯段落仅 5.0s、代码块主导 10.7s。黄金样例生成器因此按"典型构成"构造（列表/代码块均为每 150 节一个低频元素）。该边界属 pandoc 本体行为（合规边界：不改 pandoc），建议 M5 FAQ 声明。

### 关键实证记录（供后续里程碑复用）

1. `--metadata key=value` 按第一个 `=` 分割，值中冒号安全（`title=a:b` 完整保留）。
2. 无效 TeX 公式：退出码 0 + stderr `[WARNING] Could not convert TeX math …, rendering as TeX`，产物中为原文文本（不产出 `<m:oMath>`）。
3. `--toc` 在 docx 中生成 `<w:instrText>TOC \o "1-3" \h \z \u</w:instrText>` 域指令；tocDepth 映射到 `\o "1-N"`。
4. 图片抓取失败：退出码 0 + stderr 警告 + 产物中生成**单格 FigureTable 占位**（tables 计数 +1，images 0）——expected.json 已按此校准。
5. pandoc 对每张图输出 mc:AlternateContent（`w:drawing` + `w:pict` 双表示）——图片计数必须用 `wp:inline`/`wp:anchor`，否则翻倍。
6. `--number-sections` 在 docx 中表现为标题段落内 `SectionNumber` 字符样式运行（styles.xml 无差异）。
7. `pandoc --version` 首行格式 `pandoc 3.12`；Windows zip 内路径为 `pandoc-3.12/pandoc.exe`，macOS 为 `pandoc-3.12-arm64/bin/pandoc`（fetch 脚本按文件名递归查找，均已验证）。
